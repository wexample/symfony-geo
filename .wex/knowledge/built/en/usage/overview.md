`wexample/symfony-geo` is a Symfony bundle that ships `Continent` and `Country` Doctrine entities populated from the `rinvex/countries` dataset, each carrying ISO codes and a relationship to the currency entity from `wexample/symfony-money`. It is aimed at Symfony developers who need a ready-made geographic reference layer — with repositories, seed services, and API import endpoints — without writing the boilerplate themselves. `php bin/console geo:seed` writes the continents and countries from the command line (`money:seed` first, so a country finds its currency); the `_geo/continent/import` and `_geo/country/import` endpoints do the same for an application with someone to click them.

## Addresses

`PostalAddressInterface` is a postal address whose country is a relation to `Country`: no ISO code is stored outside the country table. Entities get the columns from `HasPostalAddressTrait`; `AbstractAddress` adds an addressee for address books. `PostalAddressHelper::toLines()` gives the lines as printed on an envelope, the country by its name.

**An address is a relation, never columns copied into its owner.** `Address` is the concrete entity of the shared `address` table: an organization, a user, anything with an address points at one with a `ManyToOne`, and a move is written on that row once for all of them. `AddressRepository::saveNewAddress()` writes one; `createNewAddressFromAddress()` makes a separate copy where two owners must move apart.

The exception is what must not move: a document already issued. An invoice, an order, a shipment keep an `AddressSnapshot` — the lines, the post code, the city, and the country as its code and its name, text and not a relation — taken with `AddressSnapshot::fromAddress()` the day they were issued, in columns of their own (it is an embeddable) or as JSON through `toArray()`/`fromArray()`.
